No native toolchain on the macOS host (no TBB/Boost/jsonnet/Catch2). Use the local `phlex-dev` image:

```bash
cd /Users/greenc/work/cet-is/sources/phlex/phlex
podman run --rm -v "$PWD":/workspaces/phlex:Z -w /workspaces/phlex \
  localhost/phlex-dev:2026-10-09-aarch64 bash -c '
    source /entrypoint.sh >/dev/null 2>&1 &&
    cmake --build build-prefs &&
    ctest --test-dir build-prefs -N &&
    ctest --test-dir build-prefs -j8 --output-on-failure --no-tests=error --timeout 300'
```


## 4. Things that will bite

- D16 adds the association concept, but `make_type_id<T>()` still returns an invalid ID for other unsupported non-aggregate classes (`0xFF` branch with a `FIXME`). Association child IDs use existing structural concepts; they are not a replacement for exact RTTI. The generic fallback was deliberately not changed.
- `product_selector::match(spec)` (two-argument form) does **not** check layer or stage; only the three-argument form does. The resolver therefore checks cell and stage itself (`resolution_target::identifies`).
- `transform_node` creates a *new* store per invocation that shares the input's cell index. A cell does not have "a" store; the reviewer's point about 09-17's `CellRegistry` having nothing to attach to rests on this.
- `repeater_node` re-emits the *same* store pointer with a new message id, which is why exact-cell matching survives ancestor-layer repetition. If the scheduler ever copies products into child cells, `cell_coordinate::matches` must change.
- `prek`'s clang-format hook rewrites files in place; always rerun after any edit, and the test files are the ones it has touched most.
- The LSP on the host reports hundreds of false errors for every framework header (no compile database on macOS). Ignore it; the container build is authoritative.
- `model-guru-select` currently refuses with a catalog/config hash mismatch; run `model-guru-refresh` only with explicit authorisation. The recommendation below was made from agent files and the routing reference directly.
